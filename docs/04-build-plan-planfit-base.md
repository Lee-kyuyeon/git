# 04. 개발 계획: 플랜핏 뼈대 + 3개 앱 장점 결합

> 이 문서는 02 기획서의 MVP 범위를 **대체**합니다.
> **개인용 프로젝트**입니다. 판매하지 않으므로 결제, 구독, 무료/유료 구분은 설계하지 않습니다.
> **운영 비용 0원**이 조건입니다. 서버, 유료 API, 유료 클라우드를 쓰지 않고 모든 것이 폰 안에서 동작합니다.
> 원칙: 사용자 흐름과 정보 구조는 플랜핏 방식(추천이 먼저, 기록은 그다음)을 따릅니다. 각 화면에 짐워크, 플릭, 데일리핏의 강점을 끼워 넣고, 플랜핏 리뷰에서 나온 약점은 처음부터 막습니다.
> 디자인, 문구, 영상, 브랜드는 독자적으로 만듭니다. 가져오는 것은 **기능 구조**뿐입니다.

---

## 1. 뼈대: 플랜핏에서 가져올 구조

플랜핏의 핵심은 **"앱을 열면 오늘 할 운동이 이미 정해져 있다"** 는 점입니다. 이 흐름을 그대로 뼈대로 씁니다.

```
온보딩(목표, 경력, 장소·기구 등록)
  → 오늘의 운동 자동 추천 (종목, 세트, 무게, 횟수)
  → 운동 플레이어 (세트 체크, 휴식 타이머, 동작 가이드, 대체 운동)
  → 운동 완료 피드백 → 다음 추천에 반영
  → 기록 (캘린더, 일지, 체중) / 커뮤니티
```

| 뼈대 모듈 | 플랜핏 기능 | 우리 구현 |
|---|---|---|
| A. 온보딩 | 목표별(다이어트, 벌크업, 힙업 등) 설정, 헬스장/집 기구 등록 | 목표, 경력, 빈도, 시간, **장소 프로필(여러 개)** |
| B. 오늘의 운동 | 매일 운동 자동 추천 | 주간 프로그램 + **회복도 기반 당일 조정** |
| C. 운동 플레이어 | 세트/휴식 관리, 음성 코칭 | 세트 기록, 자동 휴식 타이머, 음성 안내 |
| D. 운동 가이드 | 동작 설명, 대체 운동, 웜업/스트레칭 | 동작 요령, 흔한 실수, 대체 종목, 자동 웜업 세트 |
| E. 기록 | 캘린더, 일지, 체중/인바디 | 캘린더, 세션 상세, 체중·체성분 |
| F. 건강 연동 | Apple 건강 동기화 | HealthKit / Health Connect |
| G. 커뮤니티 | 팔로우, 공유, 댓글 | 친구, 기록 공유 이미지 (3단계) |
| H. 워치 | Apple Watch | 3단계 |

## 2. 붙일 장점: 다른 앱에서 가져올 것

### 2.1 짐워크 → "추천의 정교함"과 "성장 시각화"

|---|---|---|

| 부위별 볼륨 그래프, RPE 추이 | E. 기록 | |

| 친구 볼륨 랭킹 | G. 커뮤니티 | 3단계 |

### 2.2 플릭 → "빠르고 가벼운 기록"
| 장점 | 붙일 위치 | 비고 |
|---|---|---|
| 최소한의 탭으로 기록: 이전 값 자동 채움, ✓ 한 번으로 완료 | C. 플레이어 | 추천 앱 특유의 무거움을 덜어 줌 |
| **종목별 메모** (트레이너 코칭 내용 등) | C, D | 메모는 이전 세션에서 이어서 보이게 |
| 부위별 종목 탐색 | D. 라이브러리 | |
| 자유 운동 모드 (추천 없이 바로 기록) | B. 홈 | 플랜핏 사용자 중 "내 루틴대로 하고 싶은" 사람용 |
| 유산소 기록 (시간, 거리, 칼로리) | C, E | |
| 트레이너–회원 공유 | 제외 | 개인용이라 불필요 |

### 2.3 데일리핏 → "몸 상태 배려"와 "지속 동기"
| 장점 | 붙일 위치 | 비고 |
|---|---|---|
| 불편 부위(어깨, 허리, 무릎) 종목 자동 제외 | A, B | `core/routineGenerator.ts` 구현됨 |
| 운동 시간 30~90분에 맞춘 루틴 길이 | B | 구현됨 |
| 음성 세트 안내 + 반복 카운트 | C | 플랜핏 음성 코칭과 합침 |
| 연속 기록, 레벨, 업적, **연속 기록 보호권** | B. 홈 | `core/streak.ts` 구현됨 (주 단위) |
| 1RM 성장 리포트, 정체기 분석 | E. 기록 | 1RM 구현됨, 정체기 판정은 신규 |
| AI 코치 채팅 ("오늘 허리 아파", "30분밖에 없어" → 루틴 수정) | B | **온디바이스 LLM** (7장) |
| 백업 | 전체 | 서버 대신 백업 파일을 iCloud Drive/Google Drive에 저장 |

## 3. 플랜핏 약점 보완 (리뷰 근거)

| 약점 | 대책 | 모듈 |
|---|---|---|
| 첫 추천 무게, 세트가 너무 낮음 | 온보딩에서 대표 종목 무게 입력(선택) → `coldStartWeight` | A |
| 운동 후 체감 난이도로 자동 조절 요청 | ✓ 길게 눌러 RPE 입력 + 운동 종료 시 "전체 난이도" 1문항 | C |
| 메모, 기록 소실 | 로컬 DB 즉시 저장, 자동 백업 파일, 내보내기 | 전체 |
| 워치, 백그라운드 타이머 오류 반복 | 타이머를 "종료 시각" 기준으로 계산(경과 시간 누적 금지), 로컬 알림 예약 | C |

## 4. 화면별 결합 결과

### 홈 (오늘)
```
┌ 이번 주 3/4회 · 🔥 연속 5주            ← 데일리핏 스트릭
├ [오늘의 운동] 상체 B · 52분 · 6종목     ← 플랜핏 자동 추천
│   "가슴 회복 65%라 등 위주로 바꿨어요"  ← 짐워크 회복도로 당일 조정
│   [시작]  [종목 바꾸기]  [자유 운동]     ← 플릭 자유 모드
└ 회복도 인체 맵 (요약)                   ← 짐워크
```

### 운동 플레이어
```
바벨 벤치프레스                [가이드] [대체] [메모]
 메모: "팔꿈치 45도" (지난번)              ← 플릭 메모
 웜업  40kg×8  60kg×5  80kg×3             ← 플랜핏 웜업
 1  지난번 95×10 │ 97.5 × 8  ✓            ← 짐워크 추천, 플릭 빠른 입력
 2  탑세트       │ 97.5 × 8  ✓(길게: RPE)
 3  백오프 -10%  │ 87.5 × 10 ✓            ← 짐워크 세트 타입
 ── 휴식 1:47 ─ [−15s][+15s][건너뛰기]     ← 자동 시작, 음성 안내
```

### 운동 완료
총 볼륨, PR 배지, 소요 시간 → "오늘 어땠나요? 쉬움/적당/힘듦" (플랜핏 피드백) → 공유 이미지(2단계)

### 기록
캘린더(플랜핏) / 부위별 볼륨(짐워크) / 1RM 그래프·정체기(데일리핏) / 체중·체성분(플랜핏)

### 2단계 (6주), "분석 + 로컬 AI"
- 음성 세트 안내, 반복 카운트
- 1RM 리포트, 정체기 분석, 회복도 상세

- HealthKit / Health Connect 연동, 기록 공유 이미지, 유산소 기록

### 3단계, "소셜 + 기기"
- 친구, 팔로우, 볼륨 랭킹, 댓글
- Apple Watch / Wear OS: 세트 체크, 휴식 진동, 심박
- 체성분 검사지 촬영 입력(OCR)


## 6. 1주차 `core` 추가 작업 상세

| 함수 | 입력 → 출력 | 출처 |
|---|---|---|
| `dailyAdjust(programDay, recovery, profile)` | 오늘 예정 운동 + 회복도 → 회복도 60% 미만 부위 종목을 다른 부위로 교체하거나 세트 축소 | 플랜핏 + 짐워크 |
| `buildSetPlan(rec, type)` | 추천 무게 + 세트 타입(일반, 탑/백오프, 드롭) → 세트 목록 | 짐워크 |
| `detectPlateau(history1RM)` | 종목별 1RM 시계열 → 최근 4주 기울기 ≤ 0 이면 정체 + 처방(세트 타입 변경, 종목 교체, 디로드) | 데일리핏 |
| `sessionFeedbackAdjust(program, feeling)` | 운동 후 "쉬움/힘듦" → 다음 세션 세트 ±1, 휴식 ±15초 | 플랜핏 |
| `LocationProfile` | 장소별 기구 세트(헬스장 A, 집) → 루틴 생성 시 선택 | 플랜핏 |


## 7. 로컬 AI 코치 (무료, 오프라인)

### 7.1 역할 분담
작은 로컬 모델이 루틴 전체를 짜면 품질이 불안정합니다. 그래서 **추천은 규칙 기반 `core`가 하고, LLM은 사용자의 말을 조건(JSON)으로 바꾸는 일만** 합니다. 이 일은 1~4B 모델로도 충분합니다.

```
"오늘 허리가 좀 뻐근하고 30분밖에 없어"
   │  로컬 LLM (JSON 스키마로 출력 고정)
   ▼
{ "injuries": ["lowerBack"], "minutes": 30, "skipMuscles": [], "intensity": "lower" }
   │  core.generateProgram / dailyAdjust
   ▼
허리 부담 종목(바벨 로우, RDL)을 빼고 30분 루틴으로 다시 생성 → "허리 부담 종목 2개를 뺐어요"
```

그 밖의 용도: 운동 후 한 줄 요약, 종목 질문 답변(종목 DB의 요령 텍스트를 함께 넣어 답하게 함).

### 7.2 실행 방법 비교 (모두 무료)
| 방법 | 지원 기기 | 장점 | 단점 |
|---|---|---|---|
| **llama.rn** (llama.cpp의 React Native 바인딩) + GGUF 모델 | iOS, Android 대부분 (RAM 6GB 이상 권장) | 기기 제약이 가장 적음, 모델 선택 자유, JSON 문법 제약 출력 지원 | 모델 파일 1~3GB 다운로드, Expo Go 불가(개발 빌드 필요) |
| Apple Foundation Models (iOS 26) | Apple Intelligence 지원 iPhone (15 Pro 이상) | 다운로드 없음, 구조화 출력 지원 | iPhone 전용, 네이티브 모듈 작성 필요 |
| Gemini Nano (Android ML Kit GenAI) | 일부 최신 Android 기기 | 다운로드 없음 | 지원 기기 한정 |

**권장**: llama.rn을 기본으로 씁니다. 모델은 1~4B급 소형 모델(예: Qwen3 1.7B/4B, Gemma 3 1B/4B의 Q4 양자화본)을 실제 폰에서 비교한 뒤 정합니다.
- 모델 파일은 앱에 넣지 않고 첫 실행 때 와이파이로 받습니다(Hugging Face에서 무료).
- 모델을 못 받았거나 기기가 느리면 AI 없이 버튼형 조건 선택(아픈 부위, 시간)으로 동작합니다. 앱은 AI 없이도 완전히 쓸 수 있어야 합니다.

## 8. 무료로 폰에 설치하기

| 폰 | 방법 | 비용 | 제약 |
|---|---|---|---|
| **Android** | APK를 빌드해 직접 설치 (`expo prebuild` 후 로컬 빌드, 또는 EAS 무료 플랜) | 0원 | 없음 |
| **iPhone** | Mac + Xcode로 무료 Apple ID 개발 서명 후 설치 | 0원 | **Mac 필요**, 설치한 앱이 **7일마다 만료**되어 다시 설치해야 함 |
| iPhone (참고) | Apple Developer Program | 연 $99 | 1년 유지, TestFlight 가능. 무료 조건이면 제외 |

→ 무료 조건만 보면 **Android가 훨씬 편합니다.** iPhone이면 Mac이 있어야 하고 주기적인 재설치를 감수해야 합니다.

## 9. 리스크

| 리스크 | 대응 |
|---|---|
| 운동 영상 제작 부담 | 일러스트 + 요령 텍스트로 시작, 필요하면 직접 촬영 |
| 로컬 LLM 품질이 낮음 | 추천 자체는 규칙 기반(`core`)이 담당. LLM은 말을 JSON 조건으로 바꾸는 일만 하므로 작은 모델로 충분 |
| 모델 파일 용량(1~3GB) | 첫 실행 시 와이파이에서 다운로드, 앱 번들에 넣지 않음 |
| 기능 과다로 플릭 같은 가벼움 상실 | 플레이어 화면은 기본 상태에서 버튼 3개 이하 유지, 나머지는 길게 누르기나 시트로 |
